# host0002: a kind compiled into the binary against the tool built from a checkout

**Question.** `velocity worker` runs a job by cloning this repository, building
`cmd/tools/<tool>` at the job's commit with `-tags pcap`, and running the result. That makes the
worker a build farm: it needs git, a Go toolchain and libpcap headers, and a job is reproducible
only as far as a checkout is. The review proposes that a worker runs kinds compiled into the
binary it was shipped, with the job recording the build version, the tuning fingerprint and the
capture digest. Does an in-process kind produce the rows the built tool produces, and how much
sooner does a job answer when nothing is compiled first?

**Arms.** `built`, the worker as it is today, building the tool at HEAD; `inbinary`, the same
analysis as a kind in the static binary the worker was started from. Both run the defaults.

**Measures.** Row-for-row identity of the baseline's track and estimate rows between the two
arms on each case (identifiers, frame indices, positions to a millimetre, speeds to a
centimetre a second); wall time from claim to first result row and from claim to the bundle;
the bundle's recorded build version, fingerprint and capture digest.

**Rule, written before the runs (2026-10-19).** In-binary kinds replace the checkout path when
the rows are identical on all four cases and time to first result is at most half the built
arm's on every case. Identical rows with no time saving still adopts in-binary kinds, for the
provenance alone, and the report says so. Rows that differ on any case stop the adoption: the
difference is attributed (a build tag, a default read from the working directory, a clock) and
fixed before the spec is asked again.

**What could mislead.** The built tool reads `config/tuning.defaults.json` from the checkout by
walking parent directories, and the in-process kind reads the embedded copy; if the two differ
the rows differ for a reason that is a finding about configuration, not about the worker. The
report pins both fingerprints.

**What it does not establish.** Nothing across hosts: both arms run on one worker. That is
host0003.
