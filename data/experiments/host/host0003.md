# host0003: one capture under one fingerprint on three hosts

**Question.** A worker role is only useful if a job's result does not depend on which host ran
it. The scenes were rebuilt on October 18 and are "not yet reproducible" (#783); perf0003 asks
whether pacing changes a replay on one host; l3bg0021 made a replay start from nothing. What is
not known is whether the same capture under the same tuning fingerprint, in analysis mode on a
fresh process, gives the same track rows on an M1 Pro, on the Unraid blade and on a Pi 5, or
where the first row differs and why.

**Arms.** One: the defaults. The hosts are the comparison, not the arms. Every arm runs `config/tuning.defaults.json` at fingerprint `15fe4df885c8`, the value when this spec was written (2026-10-20); a run under another fingerprint is not this experiment, and the report records the fingerprint each run used.

**Measures.** For each case, the baseline's track rows compared across the two Mac repeats, then
Mac against blade and Mac against Pi: identical identifiers and frame indices; positions within
a millimetre; speeds within a centimetre a second; the first frame at which any row differs,
and the number of tracks whose lifetime differs.

**Rule, written before the runs (2026-10-19).** The within-host repeats must be identical, or the
spec stops and l3bg0021's claim is re-opened. Across hosts, identical rows on all four cases
makes a job comparable across host classes and the worker role can be scheduled on whichever
host is free. Rows that differ are attributed before anything is scheduled: floating-point
summation order, a clock read on the host (the clock plan's phases A to C), goroutine scheduling
in the frame callback, or a default read from the working directory. If the first difference is
in track identity, the deterministic track identity item (v0.5.4) is its fix and stays ahead of
the clock abstraction; if it is in positions
only, the report states the bound and a job is comparable within that bound.

**What could mislead.** The Pi runs the static musl build and the Mac a cgo build against the
system libpcap; a difference in packet timestamps from the two pcap libraries would show as a
clock difference, not a pipeline one. The report checks the decoded frame timestamps first.

**What it does not establish.** Nothing about live ingest, where UDP arrival order is the host's.
Nothing about paced replays, which perf0003 covers.
