# l5id0007: fragment endpoints on kirk, before any linker

**Question.** A linker can only be scored where truth says which fragments are one vehicle. How
many true vehicle links do kirk0 and kirk1's labelled window hold, what are their gaps in time
and distance, and how many of those gaps are occlusion (the object's returns are absent because
a nearer body covers them) rather than loss in L3 or L4 (the returns arrive and are dropped)?

**Method.** The default tracker, with `coast_support` so each expired track records whether its
absence was `occluded_inferred`, `missed_unknown` or `out_of_fov`. The `links` measure lists true
links per reviewed object; `fate` says what the returns in each gap became. Nothing is linked.

**Rule, written before the replays (2026-10-21).** This experiment decides whether l5id0008 can
be read, not whether a linker works:

1. l5id0008 proceeds on kirk when there are at least 40 true vehicle links across both captures.
   With fewer, a 0.98 precision rule cannot be told from 0.95 on kirk: l5id0008 still builds and
   runs its arms, but its rule is read on l5id0009's graded links instead.
2. If fewer than half the true links' gaps are occlusion-shaped (no returns at the object's
   bearing, `occluded_inferred` on the expiry, or both), the report says so and names the
   upstream experiment (l3bg or l4clus) that owns the rest; a linker would hide those faults.
3. The report gives the distributions of gap time and gap distance, so l5id0008's gates are set
   from kirk rather than copied from the paper's 2.5 s and 20 m.

**What could mislead.** kirk is one placement and short. A reviewed object that leaves and
re-enters coverage is a true link with no occlusion; the report separates those by `out_of_fov`.
A duplicate track overlapping another in time is not a fragment gap; l5id0006 owns duplicates.

**What it does not establish.** Any linker's precision; anything off kirk.
