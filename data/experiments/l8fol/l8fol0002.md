# l8fol0002: class evidence for the following gate

**Question.** Following is defined for rigid vehicles on both sides, and the provisional field
run on kirk0 suppressed 57 of 60 tracks because only 3 ended classed as rigid vehicles. Nothing
measures classification accuracy today. On the two labelled kirk captures, what share of reviewed
vehicles' tracks end classed car, truck or bus, at what track age does the class arrive, how many
pedestrians and cyclists are classed as vehicles (the gate's false applicability), and how do
those move with one track per vehicle and under the L3 retune, whose tracks are longer?

**Method.** A new measure in the per-frame evaluator, scored on the tuning split of each kirk
capture under four arms. The class read is the one the following adapter reads: the track's
classifier label and confidence, as `solidBodyClass` and `PassageFromL5` take them.

**Reading, written before the replays (2026-10-18).** A measurement; no default changes. Per arm
and capture: the share of reviewed vehicle objects whose track ends rigid; the share of their
reviewed frames at which the track is already rigid; the age at first rigid class (median and
p90); false applicability (reviewed pedestrians and cyclists whose track ends car, truck or bus).
What the numbers decide: if under the best arm fewer than four in five reviewed vehicles end
rigid, the class gate, not the geometry, is what hides following in a field run, and the
classifier plan's scorecard moves ahead of the endpoint work; if four in five or more do, the gate
is not the binding constraint and the endpoint source (l8fol0003) is.

**Amended before the replays (2026-10-20).** Three facts found while building the measure change
how it runs, not what it reads or decides. (1) The classifier's decision is persisted only on the
solid-body rows (`lidar_track_solid_bodies.motion_class`), which a replay writes only with the
`solid_body` experiment; the defaults and the CMR set enable the box model, not the solid body,
so every arm now adds `solid_body`, which shadows the filter and never changes the tracks
(`replayeval.ExperimentSolidBody`). (2) Only kirk0 has a reviewed pack and a split; kirk1's
labels are track-level and the per-frame evaluator cannot read them, so the measure runs on
kirk0's tuning split alone, episode `whole-pack`. (3) Only `rigid_vehicle` is persisted, not
car, truck or bus, so "first classed car, truck or bus" is read as first classed rigid. The
reading's four numbers and the four-in-five threshold are unchanged. kirk0's pack also holds one
object labelled bus, which is reported apart.

**What it does not establish.** Classification accuracy on the corpus, which has no labels; the
classifier plan's acceptance, which needs its own scorecard and corpus; anything about buses,
which kirk0 does not hold.
